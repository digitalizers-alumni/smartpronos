## Nice-to-have : table `user_preferences`

Pour permettre à chaque utilisateur de conserver ses préférences (filtres actifs, tri, etc.) quel que soit son appareil :

```sql
CREATE TABLE user_preferences (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id    uuid NOT NULL UNIQUE REFERENCES profiles(id) ON DELETE CASCADE,
  prefs      jsonb NOT NULL DEFAULT '{}'::jsonb,
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

- `prefs` en jsonb pour flexibilité (filtres, thème, tri, etc.)
- Clé UNIQUE sur `user_id` (1 seul document par user)
- Trigger `moddatetime` sur `updated_at`
- RLS : user voit/modifie seulement ses prefs
- Appel frontend via RPC `get_user_preferences` / `set_user_preferences`
- Pas prioritaire pour le MVP — localStorage suffit en attendant

## Bugs esthétiques (non bloquants) — à corriger plus tard

### Scrollbar layout shift
Sur Windows, l'apparition/disparition de la scrollbar sur `<main>` décale le contenu de ~17px.
**Solution tentée :** `html/body { overflow: hidden }` + `<main> { overflow-y: auto }` avec `h-screen` sur le conteneur. Le scroll fonctionne mais le shift persiste.
**Piste future :** `scrollbar-gutter: stable` sur `<main>` avec un conteneur interne pour éviter le double-scrollbar.

### Card shrinking entre filtres
Quand on change de filtre, les cartes changent de hauteur de quelques pixels car les lignes de la grid CSS s'adaptent à la carte la plus haute de chaque ligne.
**Solution :** ajouter `min-h-[240px]` sur la MatchCard pour uniformiser la hauteur.
